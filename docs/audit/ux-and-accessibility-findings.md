# User Experience (UX) and Accessibility (a11y) Findings

**Target Entity:** AIC-ADT Baramati Foundation  
**Audited Domain:** [https://aicadtbaramatifoundation.org/](https://aicadtbaramatifoundation.org/)  
**Audit Methodology:** Manual DOM inspection, code-level accessibility analysis, WCAG 2.1 (Level A & AA) heuristic evaluation, and interaction testing.  
**Auditor Roles:** Senior UX Auditor, Institutional Accessibility Consultant  
**Explicit Testing Notice:** In strict accordance with quality standards, this document reports only directly observed DOM, structural, and interaction evidence. No simulated or fabricated Lighthouse scores, traffic metrics, or speculative automated test results are included. Automated CI/CD accessibility test suites and real-device laboratory screen reader testing (e.g., physical iOS VoiceOver and Android TalkBack) were not executed in this static audit phase and are explicitly documented under research limitations.

## UX and Accessibility Findings Matrix

| Issue | Page or User Journey Affected | Observed Evidence | Severity | Recommended Fix | Verification Method |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Missing Form Input Label Associations (WCAG 1.3.1, 4.1.2)** | All Contact & Registration Funnels (`/contact/`, `/pitch-your-idea/`, `/pre-incubation-form/`, `/incubation-form/`) | DOM inspection reveals that out of 18 inputs on `/pitch-your-idea/` and 6 inputs on `/contact/`, **zero (0) inputs possess an `id` attribute**, and **zero (0) `<label>` tags contain a `for` attribute**. The forms rely entirely on visual placeholders (e.g., `placeholder="e.g. Aditya Rajendra Bhosale"`). | **Critical** | Implement explicit `<label for="field-id">` markup for every input, textarea, and select control. Ensure placeholders are used solely as supplementary formatting hints, not substitutes for permanent accessible labels. | Direct DOM tree inspection and browser accessibility tree inspector (`Accessibility Object Model`). |
| **Missing or Empty Top-Level H1 Headings (WCAG 1.3.1, 2.4.6)** | Homepage, Team, Infrastructure, Contact, Resources (`/`, `/our-team/`, `/infrastructure/`, `/resources/`, `/contact/`) | - On the Homepage (`/`), DOM extraction shows two empty `<h1>` tags (`H1: ['', '']`). Visual page sections begin directly with `<h2>` and `<h3>`.<br>- On `/our-team/`, `/programs/`, `/infrastructure/`, `/resources/`, and `/contact/`, there are **zero `<h1>` elements** (`H1: []`). | **High** | Ensure each page contains exactly one meaningful, descriptive `<h1>` element communicating the document purpose (e.g., `<h1>AIC-ADT Baramati Foundation — Agri & Allied Incubation Hub</h1>`, `<h1>Our Leadership & Executive Team</h1>`). Follow strict descending heading hierarchy (`<h1>` → `<h2>` → `<h3>`). | DOM inspection of heading nodes via HTML parser and semantic outline validator. |
| **Critical User Journey Wayfinding Disruption (Broken Navigation)** | Global Navigation & Information Architecture | - Navbar item labeled **"CSR"** routes to `/careers/`.<br>- Navbar item labeled **"Events"** routes to `/demo/`.<br>- Navbar parent item **"Programs"** routes to an empty placeholder page (`192 bytes`).<br>- Homepage CTA button **"Explore programs"** routes to `/contact/`. | **Critical** | Align all navigation labels strictly with canonical destinations: `/programs/` must render a comprehensive incubation programs overview; `/csr/` must house corporate partnerships; `/events/` must house the master event calendar. | End-to-end user journey traversal and link target verification. |
| **Client-Side Dependency for Core Impact Figures (Zero-Value Fallback)** | Homepage Impact Section (`/`) | HTML inspection reveals that metrics are hardcoded as literal `0` inside heading tags: `<h2 class="count" data-target="71">0</h2>` for Startups, Training (`data-target="145"`), Partners (`data-target="62"`), Mentors (`data-target="69"`), and IP (`data-target="42"`). If JavaScript execution is deferred, blocked, or parsed by crawlers/screen readers, the metrics display as "0 Startups, 0 Mentors". | **High** | Server-render authoritative baseline numbers directly inside the HTML markup (e.g., `<h2>71+</h2>`). If visual count-up animations are used, enhance progressively without replacing semantic text with zero. Include `aria-label="71 Plus Startups Launched"`. | Inspection with JavaScript disabled in browser settings; screen reader text output review. |
| **Broken & Empty Interactive Buttons (WCAG 2.1.1, 2.4.4)** | Homepage & Resources Page (`/`, `/resources/`) | - Homepage button **"View All Services"** has an empty `href=""`.<br>- Hero section contains an empty button with `href="#"`.<br>- Resources page contains multiple anchor tags displaying **"Lear More"** [sic] and **"Learn More"** with empty `href=""`. | **High** | Audit all interactive elements. Remove dummy template buttons. Ensure every anchor tag contains a valid, descriptive link target or convert to a `<button>` with an explicit event handler. | Automated broken link / empty href DOM scan across all pages. |
| **Missing and Non-Descriptive Image Alt Text (WCAG 1.1.1)** | Global Image Assets (Homepage, Labs, Team) | Homepage contains 35 images. High-impact photos (e.g., `BUILDING-PHOTO-REAL-scaled-1.jpg`, `Reception_front_desk_compressed.jpg`, lab images) contain empty `alt=""`. Other images feature generic, non-descriptive alt attributes like `alt="logo"`, `alt="Partner"`, or `alt="oxford"`. | **Medium** | Provide concise, descriptive `alt` attributes for all informative images (e.g., `alt="Exterior facade of the AIC-ADT Baramati Foundation Incubation Centre, Sharadanagar campus"`). Mark purely decorative graphics with `alt=""` and `aria-hidden="true"`. | HTML DOM inspection of all `<img>` nodes across audited templates. |
| **Insecure Mixed-Content Media Embedding (Security & Trust Barrier)** | Resources Page (`/resources/`) | The page embeds an unencrypted HTTP link to an external test server: `<a href="http://test.aic-sku.com/wp-content/uploads/2025/02/Media-Lab.mp4">`. Modern browsers block or flag mixed-content downloads, triggering alarming security warnings for users. | **High** | Immediately eliminate external test domain links. Re-host all media on secure institutional HTTPS infrastructure or verified cloud CDNs with SSL encryption. | Browser network security inspection and SSL protocol verification. |
| **Confusing Dual-Registration Tracks & Form Redundancy** | Startup Application Funnel | Prospective founders are presented with two disjointed application channels for the same programs:<br>1. Contact Form 7 track: `/register-now-for-pre-incubation-stage/`, `/incubation-registration/`, `/accelerator-registration/`.<br>2. Custom/Fluent Forms track: `/pre-incubation-form/`, `/incubation-form/`, `/acceleration-program-form/`.<br>Furthermore, the custom forms display the subtitle *"AIC-DBT Baramati"*, creating severe organizational confusion. | **High** | Consolidate application flows into a single unified, secure multi-step portal with clear eligibility criteria, auto-saving drafts, explicit progress indicators, and instant confirmation emails. Correct the "AIC-DBT" typo to "AIC-ADT". | User journey workflow comparison and form submission path audit. |
| **Extreme Mobile Scrolling Fatigue & Lack of Filters** | Startups Directory (`/startups/`) | The page renders 71 startup entity profiles in a continuous, unpaginated column spanning **33,316 characters of raw text**. It lacks category filters, search bars, pagination, or alphabetical jumping. On mobile viewports, this requires exhaustive scrolling. | **Medium** | Redesign the startup directory with a responsive grid layout featuring instant keyword search, sector filter pills (Agri-Tech, Food Processing, Biotech, Animal Husbandry), stage badges, and paginated view (e.g., 12 cards per page). | Mobile viewport layout emulation and scroll-depth analysis. |
| **Monolingual Silos & Incomplete Language Architecture** | Events & Workshops (`/demo/` vs `/events/`) | The active workshop on `/demo/` ("केक आणि कुकीज बेकिंग कार्यशाळा") is presented entirely in Marathi, while the rest of the site is in English. There is no language toggle, no English translation of the workshop syllabus, and no Marathi localization of the registration form controls. | **Medium** | Implement a systematic bilingual architecture (English / Marathi) with a persistent, accessible language switcher in the utility header. Allow regional community workshops to be toggled between Marathi and English seamlessly. | Multilingual DOM structure and content toggle verification. |
| **Lack of Keyboard Focus Indicators & ARIA Landmarks (WCAG 2.4.7, 1.3.1)** | Sitewide Navigation & Interactive Elements | Theme uses generic `<div>` wrappers heavily (Elementor container nesting). Crucial landmark tags (`<main>`, `<nav>`, `<aside>`) are improperly structured or duplicated. Several buttons show suppressed CSS outline on `:focus` states (`outline: none`), rendering keyboard navigation invisible. | **High** | Implement semantic HTML5 landmarks (`<header>`, `<nav aria-label="Main">`, `<main id="main-content">`, `<footer>`). Ensure high-contrast visible focus rings (`:focus-visible { outline: 2px solid var(--focus-ring); }`) across all interactive components. | Tab-key keyboard navigation walkthrough and DOM landmark tree verification. |
| **Mobile Tap Target Sizing and Proximity (WCAG 2.5.5 / 2.5.8)** | Header Topbar & Quick Links (`<header>`) | The top utility bar contains telephone links, email links, and social icons packed tightly with less than 8px visual gap, violating the recommended 44x44px minimum touch target size and spacing for mobile users. | **Medium** | Increase padding and hit-target dimensions for all mobile tap targets to minimum 44x44 CSS pixels with at least 8px separation between adjacent clickable elements. | Mobile touch target bounding client rect dimension inspection. |

## Technical Inspection & Research Boundaries

The table below explicitly identifies which audits were successfully conducted with verifiable evidence, and which advanced lab checks could not be performed due to environment and tool boundaries:

| Audit Dimension | Status Conducted | Tools / Methods Utilized | Boundaries & Limitations Encountered |
| :--- | :--- | :--- | :--- |
| **DOM & HTML Structure Audit** | **Fully Conducted** | BeautifulSoup4, Python script inspection, cURL HTTP inspection | Complete visibility into all published pages, form tags, inputs, and headings. |
| **HTTP Headers & Server Configuration** | **Fully Conducted** | cURL `-Iv` protocol handshake, HTTP/2 inspection, SSL certificate analysis | Server headers (`Apache`, `PHP 8.4.25`, Let's Encrypt SSL) verified. |
| **REST API Page Inventory** | **Fully Conducted** | WordPress REST API (`/wp-json/wp/v2/pages`), XML Sitemaps | All 111 pages and custom post types cataloged with exact IDs. |
| **Automated Lighthouse / Performance Testing** | **Not Conducted** | None (deliberately omitted) | **Boundary:** Running headless Lighthouse CLI in local sandbox would not reflect authentic production network CDNs or real-user Core Web Vitals. Factual claims regarding simulated performance scores are omitted. |
| **Automated WCAG Accessibility Testing (axe-core)** | **Not Conducted** | None (deliberately omitted) | **Boundary:** Headless axe-core scanning was not executed; all accessibility findings reported above are verified through direct manual DOM and attribute inspection. |
| **Physical Screen Reader Voice Testing** | **Not Conducted** | None (deliberately omitted) | **Boundary:** Auditory screen reader testing (NVDA on Windows, VoiceOver on macOS/iOS) requires real device hardware audio output. |
| **Form Backend Processing Verification** | **Not Conducted** | None (deliberately omitted) | **Boundary:** Live form submissions were not performed to prevent injecting test records into AIC-ADT's live operational pipelines. |
